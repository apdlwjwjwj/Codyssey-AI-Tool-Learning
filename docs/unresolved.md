# 미해결 기록 (Unresolved Issues)

프롬프트 규칙을 구체화하고 반복 수정했음에도 불구하고, 현재의 텍스트 기반 프롬프트만으로는 원하는 품질과 정확도를 달성하지 못한 한계 과업 2건을 기록한다.

---

## [미해결 1] 지문 내 개념만으로 새로운 수치 계산형 기출문제 창작하기

### 시도한 프롬프트 원문
```text
아래 운영체제 CPU 스케줄링(FCFS, SJF, Round Robin) 개념 설명 지문만 사용하고 외부 공식이나 예시는 절대 쓰지 않은 채로, 프로세스 4개의 도착 시간과 실행 시간이 꼬여 있는 평균 대기 시간 계산 기출문제를 새로 창작하고 정확한 정답과 풀이 과정을 출력해 줘.

[학습 지문]
FCFS는 준비 큐에 도착한 순서대로 CPU를 할당하는 비선점형 스케줄링이다. SJF는 실행 시간이 가장 짧은 프로세스에 먼저 CPU를 할당하는 방식이다. Round Robin은 각 프로세스에 동일한 시간 할당량(Time Quantum)을 부여하고, 시간 내에 완료되지 않으면 준비 큐의 맨 뒤로 보내는 선점형 스케줄링이다.
```

### 받은 결과 및 한계
- 프로세스 4개(P1~P4)의 도착 시간과 실행 시간, 시간 할당량을 임의로 설정해 문제를 만들었으나, 풀이 과정에서 문맥 교환 시점의 잔여 실행 시간을 잘못 계산하여 최종 평균 대기 시간 정답이 틀리는 산술·추적 오류가 발생했다.
- 프롬프트에 "단계별로 간트 차트를 텍스트로 먼저 그린 뒤 계산하라"고 2회 수정해 보았으나, 조건이 복잡해질수록 중간 시간 계산이 어긋나는 현상이 반복되었다.

### 막힌 이유
외부 지식 금지 규칙을 유지한 상태에서 새로운 수치 시나리오를 창작하면, LLM이 텍스트 확률 예측만으로 시간 흐름별 큐 상태 변화와 잔여 시간 뺄셈을 동시에 정확히 추적하지 못한다. 시험 대비용 계산 문제는 AI가 임의로 창작하게 두면 오답을 학습할 위험이 크므로, 계산형 문제는 AI에게 맡기지 않고 실제 기출문제 원문과 정답을 사람이 직접 입력해 해설 구조화만 맡기는 방식으로 역할을 제한해야 한다고 판단해 미해결로 남겼다.

## [미해결 2] 복수 조건(글자 수 + 개념 대조)을 동시에 만족하는 객관식 오답 선지 생성

### 시도한 프롬프트 원문
```text
아래 데이터베이스 정규화 지문에서 '이행적 함수 종속 제거'와 '결정자가 후보키가 아닌 함수 종속 제거'의 개념을 비교하는 4지선다 객관식 1문제를 출제하되, 4개의 보기 문장 모두 반드시 띄어쓰기를 제외한 글자 수가 25자 이상 30자 이하가 되도록 정확히 맞춰서 출력해 줘.

[학습 지문]
제1정규형(1NF)은 모든 속성의 도메인이 원자값만으로 구성되어야 한다. 제2정규형(2NF)은 부분적 함수 종속을 제거하여 완전 함수 종속을 만족해야 한다. 제3정규형(3NF)은 이행적 함수 종속을 제거해야 한다. 보이스-코드 정규형(BCNF)은 모든 결정자가 후보키가 되도록 함수 종속을 제거해야 한다.
```

### 받은 결과 및 한계
- 정규화 개념 자체는 정확하게 반영했으나, 4개 보기의 띄어쓰기 제외 글자 수가 각각 22자, 34자, 27자, 31자로 출력되어 지정한 글자 수 범위를 벗어났다.
- "출력 전에 각 보기의 글자 수를 직접 세어보고 범위를 벗어나면 다시 작성하라"고 프롬프트를 3회 수정했으나, 여전히 1~2개 보기의 글자 수 제약이 깨졌다.

### 막힌 이유
LLM은 텍스트를 글자 단위가 아닌 토큰(Subword) 단위로 처리하기 때문에, 정확한 음절·글자 수 제약과 내용의 논리적 정확성을 동시에 만족시키는 데 구조적 한계가 있다. 실제 시험 문제 생성에서도 엄격한 글자 수 통제는 불필요한 제약이므로, 프롬프트로 해결하려 하기보다 후처리 프로그램이나 사람이 직접 다듬는 영역으로 분리해야 한다고 판단해 미해결로 남겼다.
